# Просмотр боевых мини-игр

Кнопка «▶ Смотреть» появляется при активной мини-игре другого игрока в обычных
боях и рейдах. Зритель явно открывает окно, не получая управление персонажем.
Поддерживаются текущие проверки попадания (v2), уклонения (v2) и блокирования (v3).
Старые мини-игры v1 не транслируются. При собственной мини-игре просмотр закрывается.

## Передача и хранение

- Источник открывает WebSocket только на время своей мини-игры.
- События управления передаются пакетами раз в 200 мс, только если есть зритель.
- Зритель воспроизводит тот же детерминированный движок локально; это не видеопоток.
- Буфер нужен для подключения посреди прохождения. Он существует только в памяти
  процесса, удаляется после закрытия всех подключений, истечения мини-игры или
  через две секунды после её окончания (проверка очистки раз в секунду).
- Записей повторов, файлов и новых таблиц БД нет. После перезапуска смотреть нечего.
- Предварительные HP в трансляции не заменяют итог боя, вычисленный сервером.

## Доступ и ограничения

`/qte-stream/{battle|raid}/{token}` принимает подписанный Telegram initData первым
сообщением, не в URL. Участие в чате и включённый модуль арены проверяются при
подключении и периодически в процессе; источник обязан быть действующим игроком
текущей мини-игры. Зритель может только выбрать доступного участника или отключиться.
Данные трансляции никогда не передаются в обработчик расчёта боя.

Лимиты одного процесса: 32 комнаты, 128 подключений суммарно, 24 подключения на
комнату, до трёх окон одного пользователя в комнате; пакет до 128 КиБ, до 2000
смен управления на мини-игру, ограничение частоты, координат и времени событий.
Медленные или некорректные соединения отключаются; сам бой продолжается.

Это однопроцессный relay для текущего aiohttp-сервера. При переходе на несколько
workers потребуется маршрутизация участников одной комнаты на один worker либо
отдельная шина сообщений с коротким TTL. Для публикации прокси должен пропускать
WebSocket Upgrade на том же домене, что и мини-приложение. Если он не пропускает
соединение, недоступен только просмотр, а обычный бой работает независимо.

## Проверки

`python -m unittest discover -s tests -p test_qte_watch.py -v`

`node tests/qte_watch.cjs`

Проверяются совпадение локальных симуляций, подключение посреди прохождения,
передача по запросу, права доступа, невозможность управлять за зрителя,
переключение участников рейда, очистка памяти и отсутствие изменений состояния боя.
