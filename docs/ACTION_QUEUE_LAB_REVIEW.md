# Общая очередь и совместная защита — изолированный прототип

Запуск: `.venv/Scripts/python.exe -X utf8 tools/preview_action_queue.py --port 8141`

Адрес: http://127.0.0.1:8141/action-queue-review

Обычная арена, Telegram, база, персонажи, награды и сохранения не подключены.
Входящий HTTP доступен только через loopback. Сервер отдаёт статику; боевых API нет.

## Обновление: очередь подстраивается под существующие мини-игры

### Следующее исправление: адресные атаки обеих сторон

В интерфейсе включён `multiTarget`. У каждого бойца собственная цель, поле защитных мини-игр, позиция, стойкость и барьер. Все атаки, направленные в одну цель, совмещаются только в её поле; атаки по разным целям не смешиваются. Противники могут бить союзников героя, а исходящие классовые атаки героя и рыцаря больше не снимают HP мгновенно: они запускают готовую мини-игру у получателя.

«Рубящий удар» первого прототипа был заглушкой, такого самостоятельного названия в текущем каталоге нет. По умолчанию рыцарь теперь использует настоящий `armor_split` — «Раскол брони». Кнопка «Показать атаку Рыцаря» выбирает поле его цели. Переключение также доступно через список и карточки участников. Наблюдение не даёт ручного управления ботом: он использует тестовый автоуворот или автоблок. Управление испытателем доступно в его собственном поле. При наблюдении другого поля испытатель остаётся без ручного движения; раунд можно поставить на паузу.

Каст завершается автоматически по очереди; отдельной мини-игры точности атакующего пока нет. Урон атак обеих сторон определяется контактами исходных защитных рисунков, а не автоматическим попаданием. Поддержка применяется выбранному союзнику. Падение героя не завершает раунд, пока его союзники живы.

Проверки: `tests/action_queue_targets.cjs` принимает исходный каталог через stdin аналогично проверке адаптера. Проверяет оба режима защиты, разные цели врагов, исходную сцену рыцаря, настоящий исходящий урон, атрибуцию по парам, независимые поля, выбранное лечение и продолжение боя после падения героя.

Ниже описано устройство предыдущей версии адаптера; упоминание автоматических собственных попаданий к актуальному интерфейсу больше не относится.

Полигон теперь загружает настоящий каталог (414 вариантов) и существующие движки `qte-unique/engine`, `qte-block/engine`, а также текущие визуализаторы. Файлы отдельных рисунков, их движки и production-визуализаторы для этого не редактировались.

`existing.js` отвечает только за запуск, общую позицию, общий щит, атрибуцию попаданий и планирование окон. `existing-view.js` убирает дублирование фона и HUD при наложении готовых визуальных слоёв. Снаряды сохраняют исходные цвета; цвет участника выделяет его карточку и сегмент очереди.

Не больше двух совместимых сцен пересекаются. По фактически генерируемым примитивам система обнаруживает безопасные области, притяжение, кольцевые ограничения и большие перекрытия поля; для них выбирает отдельное окно. Особые сцены Кита, Капеллана, Назарика и казино также не смешиваются. Это консервативная защита, не доказательство проходимости всех возможных пар: баланс совместных рисунков ещё требует проверки игроком.

При конфликтующих направлениях блока переносится целая сцена с сохранением внутренних интервалов, а не её отдельные удары. Щит использует один экземпляр существующего движка: стойкость и поворот не умножаются на число атакующих. Движение в уклонении также рассчитывается один раз. Источники попаданий имеют разные пространства идентификаторов.

Свои атаки пока автоматические. Полный серверный расчёт классовых билдов, пассивок и последствий статусных эффектов в этом полигоне не моделируется. Тестовая опора урона существующей серии — 40; сумма зависит от исходных весов и количества снарядов.

Проверка адаптера:

`.venv/Scripts/python.exe -X utf8 -c "import json; from arena_qte_unique import review_catalog; print(json.dumps(review_catalog(), ensure_ascii=True))" | node tests/action_queue_existing.cjs`

Проверяет совпадение траекторий и контактов всех 414 одиночных уклонений с исходным движком, десять одиночных блоков (включая особые сцены), общее движение, общую стойкость, разнесение несовместимых сцен и подключение к очереди.

## Проверка первого прототипа

1. Сценарий «Два атакующих» или «Три атакующих»: выпущенные разными врагами атаки идут на одном поле. У каждой свой цвет, предупреждение и бюджет урона.
2. Переключить шкалу снизу / справа. Цвет рядом с именем постоянный, номер — место завершения каста. Нажатие на сегмент показывает действие и время.
3. Изменить скорость или базовый каст любого участника: очередь перестраивается. Каждый получает ровно одно действие за раунд.
4. «Прерывание каста»: выстрел успевает сорвать заклинателя; смена своей подготовки на 6–7 секунд позволяет увидеть позднее прерывание, не удаляющее выпущенную атаку.
5. «Позднее лечение»: мало начального HP и долгий каст жреца. Сравнить с быстрым лечением / ранним барьером. Лечение не воскрешает павшего.
6. Вариант «Блок»: направление мышью, джойстиком или WASD; щит — пробел или кнопка. Поднять непосредственно перед ударом для идеального блока. Долгое удержание расходует стойкость.
7. Следующий раунд сохраняет тестовые HP/энергию и добавляет 8% энергии. Сброс полностью возвращает исходные значения.

## Условные правила, пока не утверждённые для основной игры

- Время завершения = 1,25 с общей подготовки + базовый каст / (1 + скорость × 0,018).
- Скорость не ускоряет снаряды и не выдаёт дополнительные действия.
- Энергия списывается целиком по окончании общей подготовки. Прерванный незавершённый каст возвращает половину стоимости.
- В момент завершения применяются атака, лечение, восстановление энергии или барьер. Равные по времени касты разрешаются одной группой.
- Свои атаки попадают автоматически. Здесь проверяется порядок исполнения и общая защита, а не мини-игра попадания.
- Урон распределяется между снарядами каждого навыка отдельно и считается при контакте. Броня применяется в обоих режимах.
- Противники целятся в испытателя; союзники исполняют выбранные действия автоматически. Это не многопользовательский режим.
- Третья перекрывающаяся тяжёлая область откладывается; блокируемые удары разнесены минимум на 0,56 с. Обычный блок снижает урон на 75%, идеальный — на 100%; предусмотрен пробой при истощении стойкости.
- Урон, лечение и статусы production-арены не меняются. Кровотечение, пассивки классов, инициатива полного списка навыков и серверная проверка ввода в этом этапе не переносились.
