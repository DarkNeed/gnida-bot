# Единая боевая очередь v3

## Где включена

Новые личные/рейтинговые бои и спарринги, пустошь и зеркало,
рейды со сценарными боссами, RP-встречи, бои заказов и подземелий гильдии,
боевые встречи королевств и защиты предприятий используют одну очередь.
Сохранённые активные бои без `unified_version: 3` завершаются старым движком:
открытые мини-игры и уже принятые действия не конвертируются задним числом.

## Правила

- Нажатие на навык сразу фиксирует ровно один каст. Автоповтора атак игрока нет.
- У каждого навыка есть базовая длительность. Явный `cast_base` приоритетнее
  значения по роли: мощность, расход энергии, число ударов, быстрый/разовый навык.
- Время = база / (1 + скорость × 0,035), округление до 0,05, минимум 0,75.
  Это условное боевое время, не ограничение на реальную скорость нажатий.
- Скорость и длительность фиксируются при начале каста. Долгая атака даёт
  противнику возможность завершить несколько собственных действий.
- Все готовые игроки выбирают действие; во время выбора и мини-игр часы стоят.
  После завершения своего каста игрок снова выбирает навык, не дожидаясь
  завершения более длинных кастов остальных участников.
- Завершившиеся одновременно вражеские атаки используют общее поле защиты
  с исходными индивидуальными паттернами. Урон/статусы каждого источника
  сервер проверяет отдельно. Попадания, криты, блок, уклонение и наблюдение
  используют действующие QTE и серверное воспроизведение записанных вводов.
- Энергия резервируется при выборе; реген 8% срабатывает только на следующем
  собственном действии. Перехват сохраняет стоимость 8 энергии.
- Тайм-ауты касаются только тех, кто должен выбрать навык, а не повторяют
  уже готовящийся каст. Одноразовые идентификаторы выбора защищают от дублей.
- Предел рейда — 100 действий противника (в Назарике — на текущего стража).
  Сценарные откаты не возвращают уже использованные идентификаторы выбора.

## Интерфейс

Тонкая шкала внизу поля: «сейчас» слева, будущие завершения справа.
При наведении на навык или нажатии маленькой ⓘ показываются длительность,
точка завершения и прогноз «успеешь / одновременно / враг ударит раньше».
В PvP ещё не выбранный чужой навык не раскрывается.

## Локальная проверка

`python -m tools.preview_live_queue --port 8155`

Открыть `/live-queue-review` на локальном сервере. `mode`:
`solo`, `pvp`, `encounter`, `party`, `raid`; `boss=whaler|chaplain|...`,
`qte=0|1`, `defense=block|dodge`. Для второго участника открыть итоговую
ссылку `/live-preview?...` в другой вкладке с `&actor=20`.
Сервер использует отдельную временную SQLite и тестовую авторизацию;
реальный бот и его база не затрагиваются. Тестовые маршруты не регистрируются
основным сервером бота.

Автоматические проверки: `test_unified_live`, `test_skill_cast_times`,
`test_arena_assassin`, `test_guild`, `tests/live_queue_browser.cjs`.

Общий исторический набор тестов не является зелёным: часть проверок уже
падала на предыдущем коммите, часть предполагает строгое чередование ходов
или отправляет действия без новых идентификаторов выбора. Их нельзя считать
проверками поведения v3 без адаптации сценариев. Отдельные проверки v3
покрывают реальные API, сохранение, повторные запросы, тайм-ауты, награды,
классы, сценарных боссов и совместные поля защиты.
