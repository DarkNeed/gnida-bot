# Оптимизация обработки сообщений и Mini App

## Изменения

- `settle_businesses_for_user`: вместо полного соединения предприятий с работниками и условия `OR` — два индексных поиска с `UNION`. Дубликаты владельцев удаляются; каждый владелец по-прежнему рассчитывается один раз. Добавлены индексы с первым ключом `owner_id` / `worker_id` для поиска по всем чатам. Расчёт доходов, долгов, содержания и порядок «начисления до обновления last_seen» не менялись.
- Проверка доступности класса/навыка больше не собирает весь каталог ради одного ID. Встроенный контент проверяется без SQL, пользовательский — по первичному ключу с прежней валидацией и проверкой видимости класса. Это устраняет квадратичную работу меню при большом количестве пользовательского контента.
- Валидированные пользовательские определения кэшируются по `(ID, точный JSON)`. Лимиты: 128 классов и 512 навыков. При каждом обращении возвращаются независимые изменяемые поля. Правки, скрытие, удаление, откаты транзакций и изменения через другое соединение видны сразу. Кошельки, HP, эффекты, права доступа и очередь действий не кэшируются.
- HTML арены и версии ресурсов переиспользуются, пока не меняются метаданные исходных файлов. Проверяются HTML, обязательные и необязательные ресурсы, включая появление/удаление файлов. Лимит — восемь вариантов. Политика HTTP-кэширования прежняя: HTML `no-store`, JS/CSS `no-cache`. Содержимое HTML и версии ресурсов побайтно совпали с прежней реализацией на текущем наборе файлов.

## Замеры

Локальная Windows, Python 3.13, SQLite в отдельном временном каталоге. Сравнение методов из `c97a3d44f2bc60980073461e1f44dd4518000237` с изменёнными методами на одинаковых синтетических данных. Прогрев исключён; значения — медианы в миллисекундах. У baseline уже присутствуют новые индексы, но старый запрос с `OR` не получает от них сопоставимого выигрыша.

| --- | ---: | ---: |
| Подготовка HTML арены, 100 повторов | 36,79 | 14,76 |

| Поиск предприятий для сообщения работника, 100 повторов | 15,10 | 0,06 |

Последние две строки: 10 000 предприятий, 40 000 назначений. Измеряется только поиск связанных хозяйств; само начисление доходов заменено заглушкой в бенчмарке. Строка меню с 400 навыками — стресс-сценарий, а не обещание стократного ускорения всего бота. Сеть Telegram, BotHost, загрузка картинок, холодный старт и клиентский рендер в эти числа не входят.

Воспроизведение из корня проекта:

```powershell
.venv/Scripts/python.exe tools/benchmark_performance.py --baseline-ref c97a3d44f2bc60980073461e1f44dd4518000237
.venv/Scripts/python.exe tools/benchmark_performance.py
```

Первый запуск может занимать несколько минут из-за старого алгоритма меню. Скрипт не переключает рабочее дерево, не подключает настоящую базу, не запускает polling и не обращается к Telegram.

## Проверки

- 15 новых тестов: независимость изменяемых полей, ограниченность кэшей, обновления и rollback, скрытие/удаление, внешнее соединение, повреждённые определения, быстрые проверки контента, инвалидирование файлов, совпадение результатов старого/нового поиска предприятий, использование индексов и повторное подключение БД.
- 35 тестов предприятий и миграции — успешно.
- 2 HTTP/asset-теста — успешно, включая доступность версионированных ресурсов и заголовки кэша.
- Из 191 теста арены, переключателей модулей, рынка, кузницы, сообщений, NPC, финансов и единой очереди прошли 185. Шесть падений воспроизведены с исходными методами из указанного коммита, подставленными в память тестового процесса:
  - `test_arena.ArenaStoreTests.test_concurrent_moves_only_one_succeeds`
  - `test_arena.ArenaStoreTests.test_finish_payout_and_no_slave_transfer`
  - `test_arena.ArenaStoreTests.test_wasteland_bot_moves_and_reward`
  - `test_arena_modules.ModuleTests.test_hunter_ai_ignores_locked_visceral`
  - `test_arena_market.ArenaMarketTests.test_personal_potion_atomic_and_only_once`
  - `test_arena_market.ArenaMarketTests.test_pve_has_no_timeout_and_natural_loss_still_rewards`

Итого проверено 243 теста: 237 успешных, 6 существовавших падений. Это не запуск полного набора репозитория и не заявление, что все боевые тесты исправны.

## Границы этой итерации

Не менялись баланс, частота polling, правила боя, клиентское управление и проверки членства в чате. Серверный пересчёт мини-игр остаётся синхронным под блокировкой БД: его дальнейшее распараллеливание требует отдельной проверки ревизий, сроков и транзакций, чтобы не открыть повторное применение наград или результатов. Рабочая база и запущенные демо не изменялись; обновление ещё не отправлено в GitHub.
